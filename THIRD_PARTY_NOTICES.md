# Third-party notices for OpenLeash

OpenLeash is a Tauri 2 desktop application. A built binary of it statically and
dynamically links a large number of third-party Rust crates and bundles
third-party JavaScript. This file records what is in a shipped build and the
licence each component is under.

**OpenLeash itself is MIT-licensed.** See [`LICENSE.md`](LICENSE.md). This file
describes only the third-party components.

- Generated by inspecting `src-tauri/Cargo.lock` and `package-lock.json`.
- Last verified: **2026-09-29**, OpenLeash v0.1.0.
- Regenerate before every release; the numbers below are not stable.

### MPL-2.0 — the only copyleft, and it does not bind OpenLeash

`cssparser 0.36.0`, `cssparser-macros 0.6.1`, `selectors 0.36.1`,
`dtoa-short 0.3.5`, `option-ext 0.2.0`

MPL-2.0 is **file-level** copyleft, not linking-level. Its obligations attach
only if you *modify one of these crates' own source files*: that file must stay
under MPL-2.0 and its changes must be published. Linking an unmodified copy into
a larger work — statically, dynamically, or inside a single executable — does not
place any obligation on the larger work, and MPL-2.0 imposes no requirement to
publish OpenLeash's own source.

MPL-2.0 §3.2 additionally requires that a Contributor may not "cause the Covered
Software to be Incompatible With Secondary Licenses" — this constrains how these
*five crates themselves* may be relicensed, not how they may be used. OpenLeash
does not modify or redistribute them as standalone library targets.

All five are transitive. **None is a direct dependency.**
`option-ext` comes via `dirs > dirs-sys`; the other four come via
`tauri > tauri-utils > dom_query > cssparser`. They survive into the shipped
Windows binary, so this file covers them; nothing further is required.

### LGPL-2.1-or-later — present but not triggered

`r-efi 5.3.0`, `r-efi 6.0.0` are licensed `MIT OR Apache-2.0 OR LGPL-2.1-or-later`.
A licence choice of this form means the recipient may take **any one** of the
branches. OpenLeash takes the MIT branch, so the LGPL terms never apply. This is
recorded here only so that the string is not mistaken for an obligation on a
future audit.

### Apache-2.0-only components (no MIT branch available)

`clang-sys 1.9.1`, `gethostname 1.1.0`, `gl 0.14.0`, `gl_generator 0.14.0`,
`khronos_api 3.1.0`, `similar 2.7.0`, `sync_wrapper 1.0.2`, `tao 0.35.3`,
`xcap 0.9.8`

`similar` and `xcap` are **direct dependencies** of OpenLeash
(`src-tauri/Cargo.toml`) and are Apache-2.0-only, with no MIT branch to take.
That obligation follows from *their* licence, not from OpenLeash's: shipping
OpenLeash under MIT does not disapply Apache-2.0 §4 to them, and does not
create any new §4 obligation for OpenLeash itself. In both directions the
practical rule is the same one — reproduce every dependency's notice, which is
what `NOTICE` and this file do.

own, so the constraint here is simply that nominative use must stay nominative:
the icon marks remain governed by their owners' trademark policies.

## What this file does not cover

- **OpenLeash's own licence.** MIT. See [`LICENSE.md`](LICENSE.md).
- **Model providers.** OpenLeash sends requests to Anthropic, OpenAI, Google,
  OpenRouter, Z.ai, OpenCode and others at runtime. No provider SDK is bundled;
  the calls are plain HTTPS. Each provider's terms govern that traffic, not this
  file.
- **MCP servers** are user-configured programs launched at runtime, not
  distributed with OpenLeash. Their licences are the user's responsibility.
- **Per-component copyright lines.** The tables above record names, versions and
  licences. The individual copyright and attribution statements live in each
  component's own `LICENSE` file. A release that must reproduce them verbatim
  should generate a full bundle with `cargo about generate about.hbs` (which
  resolves each crate's licence text and copyright from the registry) and
  `npx license-checker-rseidelsohn --production --json` for the npm side, and ship
  the result alongside the binaries.
